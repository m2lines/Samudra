# Discrete scalar decoder pilot

This six-run experiment compares a flat 2,048-bin classifier, a flat 8,192-bin classifier, and a conditional 128-coarse by 64-fine classifier on five-day ocean forecasts. Each decoder is trained with temperature loss alone and with losses for temperature, salinity, both velocities, and sea-surface height. All scalar forecasts are fixed bin centers selected by discrete decisions. There are no continuous scalar heads or probability-mean predictions. This is an experiment/results record and is not intended to merge.

The pilot uses a four-block, width-512 transformer and native quarter-degree 17×17 crops at two input times. All 19 target depths and all input fields are retained. Compared with the preceding width-1,024, 33×33 experiment, this reduces both network width and token count; results are a screen for decoder behavior at this size. They do not establish behavior at the larger context or model size. Restricting output depths alone would save little backbone computation because each example already queries one depth.

All six runs retain five field queries and identical input examples. Temperature-only runs set the four other fields' loss coefficients to zero. Temperature retains the same coefficient it has in all-fields training. Thus the paired comparison changes auxiliary supervision without changing query count or diluting temperature's coefficient. Shared gradient clipping and AdamW can still mediate interactions. Unsupervised field scores in the temperature-only runs are diagnostics, not forecast results. Best checkpoints for those runs use temperature NLL; all-fields checkpoints use equal-channel NLL. Primary results use final-update EMA, with raw weights shown separately.

The 8,192-bin flat and coarse/fine models use exactly the same asinh-spaced leaf centers and midpoint assignment. A leaf ID is coarse×64+fine. The coarse/fine head produces a coarse categorical distribution and a conditional fine distribution using a learned coarse-token embedding and a small shared nonlinear head. It runs after one backbone pass. We enumerate all 128 coarse branches, compute exact joint log probabilities, and use joint MAP for the primary scalar forecast. We also report greedy coarse-then-fine forecasts, coarse errors, and fine errors conditioned on the true coarse token. Exact enumeration removes greedy-search error from the primary comparison. Coarse error uses the coarse marginal argmax. Fine error conditioned on the true coarse token is an oracle diagnostic. Both decisions are discrete; the decoder introduces no continuous scalar bypass.

Training minimizes ordinary categorical negative log likelihood, with equal-channel legacy full-grid weights and the existing exact coverage/area sampling corrections. Coarse/fine loss is the sum of coarse CE and conditional fine CE, equivalent to leaf NLL. There is no density weighting or stage-loss weighting. Raw categorical NLL differs with bin resolution, so it is compared directly only between the two 8,192-leaf models. For cross-resolution likelihood comparisons, rebin probability mass onto common physical intervals before scoring; do not interpret lower native NLL as a resolution-independent gain.

Before training, audit all wet cells on 32 evenly spaced training target dates for every channel. Bounds are the maximum of the previous bounds and 1.1 times the observed absolute normalized extrema. This retains the exhaustive previous temperature audit while expanding other channels from training data. The temporal audit is sampled, so validation and training-tail diagnostics remain necessary. Bounds are fixed across all six arms and never adjusted from validation. Endpoint occupancy refers to targets assigned to either edge category, including the finite in-range part of those categories. Values outside the finite range are assigned to the edge category and decoded to its finite center. Report this occupancy and target-to-center error separately from learned forecast error. The inherited bounds and normalization are documented in the [preceding classifier report](../all-fields-classification/README.md).

Each run starts fresh with seed 20261110 and identical backbone/query initialization. The run budget is 2,000 optimizer updates, batch 256, on one GPU with microbatch 32 and accumulation eight. Each loaded date supplies 2,048 crops, or eight updates; every arm sees the same shuffled date and location streams. This increases date reuse relative to the preceding large run to keep the pilot's GPU occupied. The coverage pool and corrections are unchanged. AdamW peak LR is 2e-4, warmup 100 updates, cosine decay to 10% by update 2,000. EMA decay is 0.999 with the existing faster start.

Evaluate raw and EMA weights at 0, 1, 50, 100, 200, 500, 750, 1,000, 1,500, and 2,000 updates on four fixed validation dates and 16 locations per date/depth. Preserve every validation checkpoint, per-depth CSVs, physical RMSE, persistence, native categorical NLL, quantization error, and endpoint occupancy. The primary comparison is the fixed final update. One seed per arm is an initial screen; a second-seed confirmation and larger runs require a subsequent decision. Native regional map diagnostics can use retained checkpoints if a decoder changes scalar skill, with sample geometry and compute reported separately.

A four-update qualification precedes training and exercises all three decoder layouts. Confirm finite loss, EMA updates, discrete outputs, matching sampled temperatures/persistence, and checkpoint completion. The six production jobs are capped at two allocated GPU-hours each, with checkpoint recovery for preemption and explicit accounting of repeated work. Report the measured total including support audit and qualification. No larger run is automatically released.

Validation draws wet cells separately at each depth/date in proportion to cell area, with a fixed seed shared across arms. It estimates each channel’s full-rectangular-grid masked error using inverse-area corrections; physical wet-cell RMSE divides by wet fraction before taking the square root and multiplying by the channel standard deviation. Aggregates average channel errors equally. The [preceding classifier report](../all-fields-classification/README.md) gives the weighting formula. Four validation dates limit generalization claims.

The model constructs backbone and query parameters before the output head, preserving seeded initialization across head sizes; CPU tests verify this equality. NumPy sampling has a separate seeded generator. Reports include total and head-only parameter counts. The two-hour cap includes previous allocations of a requeued job; an arm that reaches the cap before 2,000 updates is incomplete and excluded from fixed-2,000 comparisons. Any common-earlier-update comparison must be labeled separately.
